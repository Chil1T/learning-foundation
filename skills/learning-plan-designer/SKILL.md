# 学习方案设计

把最终要做出的解释、推导、应用或实际作品，转成现在能进入的路线。计划是可修订的建议，制定计划不构成学习完成。

## 确定真正需要规划的范围

- 用于用户要求规划，或目标、交付、前提实际变化时。已有可执行下一步就复用，不因“继续”重做长计划。
- 分开长期目的、阶段交付与当前行动。目标尚在形成时先简述理解，只核对会改变选择的歧义；不要将 AI 推断写成教师、课程或用户的确定要求。
- 期限、输入资料、成果用途不明时，按它是否会改变路线决定是否询问。先推进不依赖该信息的工作，未知保持未知。
- 只读当前主题的相关计划、表达和材料。按本地职责映射计划、状态、来源、个人笔记，不要求固定文件名、应用或学习档案；缺记录时可先给聊天中的短方案。

## 从产出反推必要学习

1. 将目标表述为可观察的行为或产物：解释哪些关系、重建哪一步、对何种输入作何判断。阅读页数和材料制作可作行动，但不能替代理解证据。
2. 根据实际表达区分独立做过、帮助后能跟随、明确卡点与证据未知；不把“未观察”写成“完全不会”。
3. 找真正阻塞产出的前置。对于成熟方法，可先匹配用途、输入、前提、输出和限制；涉及改变前提、推广或承担新结论时，再深入关键论证。不把所有知识依赖变成必须先完成的整门课。
4. 需要比较路线时，比较入口、顺序、支持方式和能承担的结论范围；仅工作量不同不一定是不同路线。给推荐及原因，不要求初学者独自作专家选择。
5. 每条保留的路线给材料入口、产出检查点、启用条件和阻塞后的调整。时间未知可按成果推进，不强迫精确估时。
6. 有期限时收束能承担的最小成果，说明与完整要求的差距；不要将缩小目标声称为已满足原要求，或为了赶日历跳过必要前置。

## 安排执行与调整

- 只突出少量近期行动，其余按前置和触发条件保留。日历是安排，不是能力获得承诺。
- 初学或明确不懂时先教；在意义完整处安排本人尝试、反馈或新条件应用，不将每小段变成考试。
- 留出回原材料修补和本人重建的机会。新增材料不能替代已经暴露的缺失联系。
- 反馈显示目标误解、前提冲突、支线膨胀或投入与产出脱节时调整；没有信号不反复重开已定方向。
- 暂缓昂贵支线时说明现在用到哪层、为何足够、什么情况下必须回来。暂缓证明不能记录为掌握证明。

## 交付与授权

先给目标、真实起点、推荐路线、下一项动作与主要未知。若只需要短方案，不创建制度、题库或文件树。

有写入授权时，将详细计划维护在一处，标明建议或已选定、阶段产出、当前步骤、变更理由和旧版本入口。只更新相关主题，保留其他学习线；不生成尚未发生的作答与掌握记录。只读讨论仅聊天给方案。

用户笔记和原始来源不自动改写；计划创建不自动授权外部日历、任务、消息或提醒操作。语言、格式、目录与工具按本地选择。

执行可选交给 `concept-tutor` 或 `paper-deep-reader`；证据对齐可用 `learning-state-reconciler`。没有这些技能时，直接说明第一个可执行步骤及支持范围。由其他任务转入时，将路线和下一步交回调用方，不在此重启入口。交接携带目标、有限材料、起点证据、当前步骤、收束条件和授权，不要求其他技能重新规划。
