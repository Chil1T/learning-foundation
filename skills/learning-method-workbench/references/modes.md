# 三种维护任务

## 局部提炼

先读取用户指定的材料与其实际生效的本地规则，不把全面历史扫描作为前置。材料很少时仍可形成有限范围快照，明确它来自哪几段、保留什么、哪些适用性未知。

提炼时区分：可复用原则、实现方法、本地偏好、个人学习内容。快照包含方法的触发条件、实际行为、边界、必要引用与来源说明。只保留本次分享所需的资源；独立复制后不能依赖原工作区路径或私人文件。

用户要可安装、可分享的方法时，交付 [Agent Skills 标准](https://agentskills.io/specification) 目录 `skills/<name>/SKILL.md`，其中 `<name>` 替换为实际技能名；文件夹名与 `name` 相同，使用小写字母、数字和连字符。入口包含说明“做什么、何时使用”的 `description`，正文给出实际方法，必要引用与模板放入该技能目录。以下仅是头部格式示例，不是已验证的方法：

```yaml
---
name: local-learning-method
description: 根据当前学习目标选择一个练习检查点，并在中断时保留可继续的位置。
---
```

若用户只要分享理念或规则片段，普通 Markdown 即可；说明它是方法说明，不能声称已经是可发现、可安装的技能。不要为方法快照自造清单协议、服务端或安装工具。

个人原话、学科原文、身份信息与长期学习状态默认不进入公共方法。用户只授权方法提炼时，使用抽象描述或空白模板，不制作虚构个人记录。引用第三方资源需核实许可，不把原材料的可读性当成可再许可。

完成条件：限定材料已转成可读快照；必要引用闭合；个体内容与可复用方法分开；来源、限制和下一步可见。一次快照无需长期效果证明。

可安装快照另外检查名称与头部、相对引用、完整目录复制后可读、许可和无误带私人内容；这些只证明交付形式与边界。来源包中的 `check_release.py` 是固定八技能成品的发行检查器，不要求新生成的单技能或理念片段通过它。

## 接收与组合

先看本地目标、已有方法和指定新方法的相关部分。没有本地方法时采用最小默认；已有方法时尽量保留其入口、目录和术语，给出值得改变的差异。

对差异作明确选择：保留本地、采用新方法、组合、暂不采用。说明每个重要选择服务哪个目标；冲突涉及授权、来源或证据时先保护对应边界。不要按“新的一定更好”或“现有的不可变”处理。

只读任务交付比较建议或可应用片段。授权采用后，可将项目原则合并到已有本地入口，按需要安装选中技能或创建空白记录；不覆盖已有入口，不强迫迁移目录。缺少其他技能时当前智能体可直接执行有限任务。

需要安装时使用目标环境已有安装器或按其官方位置复制整个技能目录，先区分分发源与实际学习项目。保留所有必要引用与许可，遇同名技能先比较再决定，不静默覆盖；不要发明本产品专用安装命令或适配器。安装后按客户端说明确认发现，安装本身仍不等于采纳方法。

完成条件：下一次如何使用清楚；采用范围与未采用项清楚；写入与实际授权一致；现有资料路径仍可用。

## 反馈改进

把反馈放回实际目标：用户指出的是讲解顺序、提问频率、状态记录、工具流程，还是其他问题？只在会改变修法时核对歧义。选择最小可以观察结果的改动，不要求先收集所有历史或多用户案例。

先定位负责该行为的规则或方法，优先合并、删改既有段落，避免叠加互相冲突的要求。保留用户反馈含义；不将一次偏好变成对所有人的硬约束。

授权范围已清楚就修改；只授权讨论就给建议。检查改动文件、必要引用与仍适用的边界；记录“改动已完成”与“效果尚未观察”分别成立。下一次真实使用有反馈时再调整，不设计虚构学习者表现作为证明。

完成条件：反馈对应到具体变化或明确保留的理由；修改可审查；验证与未知范围据实记录。
